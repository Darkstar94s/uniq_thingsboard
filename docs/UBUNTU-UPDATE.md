# تحديث UNIQ على Ubuntu مع الحفاظ على البيانات

## الحالة الحالية

تعديلات الهوية في `develop` تخص الواجهة، ولا تعدّل مخطط قاعدة البيانات أو ملفات إعداد السيرفر. الكود الأساسي في هذا المستودع هو `4.4.0-SNAPSHOT` ويحدد Java 25 في `pom.xml`. رقم الإصدار وحده لا يكفي لإثبات التوافق بين نسختين SNAPSHOT؛ يجب مقارنة نسخة السيرفر بالمصدر المبني أيضًا.

لم يتم إنتاج حزمة أو اختبار نشرها على السيرفر بعد. لا تثبّت هذه النسخة قبل التحقق من إصدار السيرفر وتوافق Java وقاعدة البيانات. عند اختلاف الإصدار، اختبر ترقية مدعومة على نسخة مستعادة من قاعدة البيانات، أو انقل تعديلات الهوية إلى نفس إصدار السيرفر.

## 1. معرفة النسخة الحالية

نفّذ على السيرفر:

```bash
dpkg-query -W thingsboard
java -version
systemctl is-active thingsboard
```

حدد محليًا هل PostgreSQL على نفس الجهاز، واسم قاعدة البيانات الفعلي. لا ترسل كلمات المرور أو محتويات ملفات الإعداد.

## 2. جلب الكود

إذا كان المستودع موجودًا، نفّذ داخله:

```bash
git status --short
git fetch origin
git switch develop
git pull --ff-only origin develop
git log -1 --oneline
```

إذا ظهرت تعديلات محلية، احفظها وراجعها قبل المتابعة. لا تستخدم reset --hard أو clean لحذفها. إذا لم يوجد المستودع، استنسخه في مجلد جديد منفصل عن مسارات تثبيت الخدمة:

```bash
git clone --branch develop https://github.com/Darkstar94s/uniq_thingsboard.git
cd uniq_thingsboard
```

جلب الكود لا يغيّر البرنامج المثبت بحزمة deb. يلزم بناء حزمة مخصصة تحتوي واجهة UNIQ ثم تثبيتها؛ تنزيل حزمة ThingsBoard الرسمية لا يحتوي هذه التعديلات.

## 3. النسخ الاحتياطي قبل تثبيت الحزمة

- خذ نسخة قابلة للاستعادة من قاعدة البيانات الفعلية واختبر استعادتها في بيئة منفصلة. PostgreSQL يحتوي المستخدمين وبيانات المصادقة ولوحات المعلومات؛ إن كنت تستخدم Cassandra للقياسات، انسخها أيضًا.
- مثال PostgreSQL محلي فقط، إذا كان اسم القاعدة `thingsboard`: `sudo -u postgres pg_dump -Fc thingsboard > thingsboard-before-uniq.dump`. نفّذه في مجلد نسخ احتياطي خاص بصلاحية 700، واضبط umask إلى 077، وافحص نجاح الأمر. للخادم البعيد استخدم اتصاله الصحيح دون وضع كلمة المرور في سجل الأوامر.
- انسخ الإعدادات الحقيقية تحت `/usr/share/thingsboard/conf`؛ المسار `/etc/thingsboard/conf` قد يكون رابطًا، لذلك يجب حفظ محتواه الفعلي وليس الرابط وحده.
- احتفظ بإعدادات systemd الإضافية، وملفات البيئة الخارجية، وشهادات TLS، والملفات المرفوعة أو التخزين الخارجي إن وجدت، والحزمة السابقة للرجوع إليها.
- احفظ النسخ في مكان آمن خارج مستودع Git. خطط لفترة توقف قصيرة عند تبديل الخدمة.

## 4. تطبيق النسخة بعد التحقق من التوافق

ابنِ واختبر حزمة deb من المصدر باستخدام متطلبات هذا الفرع في جهاز بناء أو بيئة تجريبية أولًا. لا تعتمد على `build.sh` لإنتاجها: السكربت الحالي يمرر `-Dpkg.skip=true` ويعطل الحزم.

بعد نجاح بناء الحزمة واختبارها على نسخة من بياناتك، أوقف خدمة thingsboard، وثبّت الحزمة المخصصة باستخدام dpkg، واحتفظ بملفات الإعداد المحلية عند السؤال عنها. راجع أي إعدادات جديدة مطلوبة قبل التشغيل. إذا كانت نسخة الأساس نفسها ولم تتغير قاعدة البيانات فلا يلزم تشغيل سكربت ترقية لهذه التعديلات البصرية.

لا تشغّل `install.sh` أو `--loadDemo` لتحديث الهوية؛ هذه خطوات تهيئة تثبيت جديد. ولا تستخدم إزالة الحزمة مع purge أو حذف قاعدة البيانات. لا تشغّل `upgrade.sh` إلا ضمن مسار ترقية إصدار محدد ومدعوم.

أعد تشغيل الخدمة، وافحص `systemctl status thingsboard` و`journalctl -u thingsboard -n 100 --no-pager`. تحقق من تسجيل الدخول بنفس حسابك ومن المستخدمين والأجهزة ولوحات المعلومات والقياسات، ثم حدّث المتصفح لتجاوز الذاكرة المؤقتة.

إن لم تحدث ترقية قاعدة بيانات، يمكن الرجوع إلى الحزمة السابقة وإعداداتها. إذا حدثت ترقية للمخطط فقد يلزم استعادة نسخة قاعدة البيانات؛ تشغيل الحزمة القديمة وحده ليس خطة رجوع كافية.

## مرجع

[توثيق ThingsBoard للتثبيت على Ubuntu](https://thingsboard.io/docs/installation/ubuntu/) يوضح إعداد قاعدة البيانات ومسارات الإعداد. متطلبات هذه النسخة المعدلة تؤخذ من ملفات المستودع وقد تختلف عن الإصدار الرسمي المنشور.
